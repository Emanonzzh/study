## A3. 盘点逼出来的三个结论（这是本文最重要的部分）

### 结论 1：❌ 客户维度不能当主力，GPT 框架的举例在这份数据上不成立

GPT 框架的归因范例是"华东 → 产品A → **核心客户X 采购量下降**"。
**但这份数据平均每人只有 1.31 单**（78,044 人里 75% 只买过一次），**不存在"核心客户持续采购"这种业务形态**，"大客户采购骤降"根本无从谈起。

> **修正**：归因主维度改为 **商品 → 平台/渠道 → 时间**。客户维度只保留"月度活跃客户数 / 新客占比 / 复购率"这类粗粒度指标，并在文档里**如实写明客户维度信息量不足**。
>
> 顺带这一条也推翻了《框架评审》第 5 节 ④ 的客户拆分建议（`ΔR = 留存 + 新增 − 流失` 在这份数据上算得出来但业务意义很弱）。

### 结论 2：❌ 没有成本字段 → 毛利相关指标全部出局，但要把它变成"取舍"而不是"缺失"

**毛利率 / 毛利额 / 利润** 一个都算不了。这不是小问题——GPT 框架的示例报告里第一节就是"毛利率：23.6%"。

> **修正（面试话术）**：拿不到成本时，用**折扣深度 × 平台/商品结构变化**做"以价换量"的代理识别：
> "数据可得性不允许我算毛利，但'量增价减'的结构恶化可以通过 AOV 下滑 + 折扣深度上升 + 低客单平台占比上升**三者同时出现**来识别。这是在数据约束下设计代理指标，而不是假装有毛利数据。"
> —— 这段话体现的是**指标设计能力**，比"我算了毛利率"更像做过真实业务。

### 结论 3：✅ 数据里本来就有真实可归因的业务现象（不用造）

盘点发现的真实走势，每一条都是天然的分析案例：

| 真实现象 | 数据证据 | 可归因方向（下钻路径） |
|---|---|---|
| **2 月环比 -23.6%** | 689.7万 → 526.9万；2 月仅 4,898 单（全年最低） | 春节 + 2 月天数少 + 工作日少 → 需做**日历效应校正**，否则误判为异常 |
| **5~6 月订单数 +40%** | 6,539 → 9,510 → 10,559 | 是某个平台拉起还是全平台普涨？（实测：三平台同向，**大盘性增长**） |
| **下半年"量增价减"** | 订单数 11 月冲到 10,910（全年最多），AOV 却从 1,114（3月）掉到 927（11月），**-16.8%** | **量价分解的完美案例**：是结构下沉（低客单 APP 占比上升）还是普遍降价？→ 用结构效应 vs 纯价效应拆分 |
| **退款率稳定在 13%** | 各平台 12.93%~13.43% 高度一致 | ⚠️ 这个"过于一致"本身可疑（像合成数据的痕迹），**不要过度解读**，只作为指标呈现 |
| **长尾平台极小** | 微信小商店 87 单、wap网站 3 单 | **最小支持度门槛的真实用例**：这俩做统计检测必然误报 |

其中"**下半年量增价减**"是整份数据里最值钱的分析题材：真实、有业务含义、且**必须用量价结构分解才能说清**，正好是项目的技术天花板所在。

## A4. 能做 / 不能做（最终清单）

### ✅ 能做
环比增速 · 月度/日粒度趋势 · 平台/渠道/商品结构占比 · 客单价 AOV · 折扣深度 · 退款率（单量/金额双口径）· 净收入 · **量价结构分解** · 集中度（CR5/HHI）· 时段与周内分布 · 支付耗时 P50/P95 · 日粒度变点检测 · 月度活跃客户/复购率

### ❌ 不能做（必须在文档和面试中主动说明，别等被问）
毛利/毛利率/利润（无成本）· 同比（仅 1 年）· 区域维度（**数据里根本没有区域字段**！）· 销售员维度（也没有）· 客户流失归因（1.31 单/人）· 目标完成率（无 targets 表）

> ⚠️ 注意：GPT 框架里的 `regions` / `salespersons` 两张表，**这份数据完全没有对应字段**。要么放弃这两个维度，要么自己造——但造了就不是"真实数据"了。**建议放弃，把归因深度压在商品/平台/时间三个维度上**。

### ⚠️ 必须处理的数据问题
| 问题 | 处理方式 |
|---|---|
| 平台枚举与 `data_dictionary.md` 不一致（4 vs 6，还有 `web网站` 大小写） | 修正字典 + 加枚举兼容层（**这仍是你可声明的改动 #1**） |
| `channel_id` 空值 7 条 | 归入 `未知渠道`，并在数据质量报表里计数 |
| 折扣深度极端值 99.99% | 异常值检测的天然样本；报告里标注为"待核查"而非直接剔除 |
| 长尾平台（87 单 / 3 单） | 最小支持度门槛：订单数 < 30 不参与统计异常判定 |
| 2 月天数少 + 春节 | **必须做日历/工作日校正**，否则 2 月必然被误报为异常 |

## A5. 异常检测的 ground truth 怎么来（真实数据没有标注，这是硬约束）

真实数据里只有"真实波动"，**没有唯一正确答案** → 直接算 P/R 是做不到的。两个诚实做法，建议**都做、分开报**：

| 方案 | 做法 | 能给出的指标 | 诚实标注方式 |
|---|---|---|---|
| **① 专家标注集** | 从 12 个月里挑出 25~30 个"业务上确实值得关注"的事件（如 2 月春节、5-6 月放量、下半年 AOV 下滑、某商品骤降），人工写清"是否应被检出" | 命中 18/25（召回） | "25 条**人工标注**事件集" |
| **② 注入集（推荐主力）** | 保留真实数据**结构与分布**，仅对指定切片做扰动（如把某 3 个商品在 9 月某两周的订单量缩放到 -60%、某渠道单日 +300%），记录注入清单 | **精确 P/R/F1** | "在真实数据上**注入** N 个已知异常（fault injection）用于评测" |

② 是关键：它让你能写出 **"异常检测 P/R = 0.86/0.82"** 这种硬指标，而注入这个动作本身在企业里就是标准做法（混沌工程/故障注入），讲出来完全站得住。

# Part B · Phase 0 业务定义（PRD）

## B1. 用户与场景

| 角色 | 诉求 | 系统给他的东西 |
|---|---|---|
| **经营负责人（老板）** | "这个月生意怎么样？哪里出问题了？" | 一页经营报告 + TOP 异常 |
| **运营/分析师** | "11 月单量涨了但收入没涨，为什么？" | 量价结构分解 + 瀑布图 + 下钻明细 |
| **平台运营** | "微信公众号的客单价为什么降了？" | 平台维度的价效应/结构效应拆分 |

**输入**：一个时间范围 + 一个自然语言问题（或无问题，只要"月度经营报告"）
**输出**：① 结构化分析结果（JSON：指标/异常/归因贡献度） ② 叙述性经营报告（Markdown / PDF / Excel） ③ 每一步的可追溯轨迹（用了哪些工具、哪些数据、什么口径）

## B2. 分析维度矩阵（**已按数据实际能力裁剪**）

| 维度 | 支持度 | 说明 |
|---|---|---|
| 时间 | ✅✅ | 日 / 周 / 月 / 时段 / 周内，12 个月 |
| 商品 | ✅✅ | 1,001 个，**归因主战场** |
| 平台 | ✅ | 6 个（2 个长尾需门槛过滤） |
| 渠道 | ✅ | 15 个（7 条空值归"未知"） |

| 销售员 | ❌ | **数据无此字段** |
| 成本/利润 | ❌ | **数据无此字段** |

## B3. KPI 口径表（每个指标都要写清公式与口径，避免"两次问出两个数"）

| KPI | 公式 | 口径说明 |
|---|---|---|
| 订单数 | `COUNT(*)` | 一单一品，等于订单行数 |
| 下单额 | `SUM(order_amount)` | 优惠前 |
| **实付额（GMV）** | `SUM(payment_amount)` | **作为"销售额"默认口径** |
| 优惠额 / 折扣率 | `SUM(discount_amount)` / `SUM(discount_amount)/SUM(order_amount)` | |
| 客单价 AOV | `SUM(payment_amount)/COUNT(*)` | 注意与"人均消费"区分 |
| 退款单量率 | 退款单数 / 总单数 | |
| 退款金额率 | 退款金额 / 实付额 | |
| 净收入 | `实付额 − 退款金额` | |
| 环比 | `(本期 − 上期)/上期` | 月度需做日历/工作日校正 |
| 结构占比 | 维度金额 / 总金额 | 量价分解的输入 |
| 集中度 | CR5（TOP5 商品占比）/ HHI | 收入依赖度风险 |
| 复购率 | 下单 ≥2 次的客户 / 总客户 | 已知偏低（25.38%），仅作趋势观察 |
| 支付耗时 | `payment_duration_sec` 的 P50/P95 | 体验型指标 |

## B4. 验收标准（Phase 0 就要定，否则后面无法判定"做完了"）

1. 给定"2025-11 月度经营报告"，系统产出报告，其中**每一个数字都能在数据库中复算得到**（数字对账通过率 100%）；
2. 对注入集，异常检测 **P ≥ 0.80、R ≥ 0.80**；
3. "11 月量增价减"能给出**结构化归因**：量效应/价效应/结构效应三项**精确加总回总变化**（误差 < 1e-6，单测断言）；
4. 同一问题连跑两次，**所有数字完全一致**（确定性）；
5. 每个结论标明**数据来源与口径版本**。

## B5. 明确不做的（写进文档，防止范围失控）

- ❌ 上传任意 CSV 建表（真实数据已入库；上传模块留到有真实需求时再做）
- ❌ Celery / 异步任务队列（报告分钟级，同步 + 任务表足够）
- ❌ 多租户、计费、复杂 RBAC（已有 JWT，补行级权限即可）
- ❌ 同比、区域、销售员、毛利相关的一切分析
- ❌ "大数据"相关表述
