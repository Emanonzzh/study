# 6 周计划：转开发（Agent 开发 + AI 运维）每天 2 小时

> 目标岗位：**① Agent 开发工程师（初级/社招往届）　② AI 运维 / AI 应用部署运维（初级）**
> 现状：项目能上线（RAG + 三工具 Agent + Docker 公网）、有评测实验；**短板 = 手写 Python 弱、没做过 CRUD、没 code review、运维只到 Docker 单容器**
> 核心策略：**一条主线项目往上长（不新开项目）+ 两条支线（Python 手写 / 运维基础）+ 全程并行投递**

---

## 一、每天 2 小时固定模板（照做，别改）

| 时间 | 内容 | 为什么 |
|---|---|---|
| 0–30 min | **手写 Python 3 题**（先写，写完再对答案；昨天错的今天默写一遍） | 你唯一的硬短板，面试手写不过=直接淘汰 |

> 周末抽 2 小时：把本周产出合并进项目 + `git commit/push` + 更新 AGENTS.md。

## 二、Python 基础速成清单（第 1–3 周穿插，按顺序）

**每天 3 题就从这里出题**（遥感/业务场景包装）：

1. 变量与类型：int/float/str/bool、类型转换、f-string
2. 条件与循环：if/elif/else、for/range、while、break/continue、**边界条件**（空列表、单元素）
3. 列表与切片：索引（含负索引）、`append/insert/remove/pop`、切片 `[a:b]`、排序、推导式
4. 字典与集合：增删改查、`get()`、遍历 `items()`、计数、去重
5. 字符串：`split/join/strip/replace/find`、切片、格式化
6. 函数：参数（默认/关键字/`*args`）、返回值、**作用域**、多返回值
7. 文件与 JSON：`open()` + `with`、读写、`json.load/dump`、编码问题
8. 异常：`try/except/else/finally`、常见异常类型、主动 `raise`
9. 模块与包：`import`、`pip`、虚拟环境、`if __name__ == "__main__"`
10. 类与对象（够用即可）：`__init__`、self、实例属性/方法、继承
11. 常用标准库：`os / pathlib / datetime / re / collections`
12. 类型注解：`def f(x: int) -> str`、`list[dict]`（现代 Python 项目必备）

**验收**：给一个业务题（如"统计每个区域去掉异常值后的平均形变"），能 15 分钟手写出来并跑通。

## 三、CRUD 能力（第 2 周主线，面试高频）

**1) SQL 增删改查（先手写 SQL，再用代码）**
```sql
INSERT INTO datasets (name, region, method, year, accuracy, source) VALUES (?,?,?,?,?,?);
SELECT * FROM datasets WHERE region = ? ORDER BY year DESC;
UPDATE datasets SET accuracy = ? WHERE id = ?;
DELETE FROM datasets WHERE id = ?;
```
- 必会：`WHERE` 条件、`ORDER BY`、`LIMIT`、`JOIN`、`GROUP BY` 计数、**参数化查询防注入**、事务 `commit/rollback`、索引概念

**2) 用 FastAPI 把 CRUD 做成接口（给项目加"后端"）**
| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/datasets` | 新增数据集 |
| GET | `/datasets` | 列表/按条件筛选 |
| GET | `/datasets/{id}` | 查单条 |
| PUT | `/datasets/{id}` | 修改 |
| DELETE | `/datasets/{id}` | 删除 |
- 加 **Pydantic 校验**（必填/类型/范围）、统一的错误返回（404/422）
- 用 **Swagger UI**（`/docs`）自测，截图当简历素材
- 进阶（第 4 周）：换 **SQLAlchemy ORM**，数据库换 PostgreSQL（docker compose 起）

**验收**：能用 curl/Swagger 完成一套增删改查，且**数据库里能看到数据变化**。

## 四、code review 能力（每天 20 分钟，第 1 周就开始）

**训练法（三种，轮着来）**
1. **读别人的代码**：每天读 1 个 FastAPI/开源小项目的文件，写 3 条意见（哪怕只是"命名不清晰""缺少异常处理"）
2. **给自己开 PR**：项目里开新分支写功能 → 提 PR → **自己 review 一遍再合并**（GitHub 上留痕，面试能展示）
3. **找茬练习**：让 AI 生成一段**故意有 bug** 的代码，你来指出问题（我可以每天给你一段）

**Review 检查清单（背下来，面试直接能用）**
- 命名是否达意（变量/函数名）
- 边界：空值、0、单元素、超长输入
- 异常：外部调用（DB/API/文件）有没有 try/except、错误有没有吞掉
- 资源：文件/连接有没有关闭（`with`）
- 安全：SQL 是否参数化、密钥是否硬编码、是否有权限校验
- 重复：能不能抽函数/循环
- 可读性：注释是否解释"为什么"、函数是否单一职责
- 测试：有没有对应的测试或至少自测方式

## 七、两个岗位的面试八股清单

**Agent 开发（初级）**
- Agent 是什么？和直接调 LLM 的区别；ReAct / Function Calling 循环怎么走
- 工具（tool）怎么注册、模型怎么决定调用哪个；工具描述（docstring）的作用与边界
- 多轮记忆怎么存；上下文超长怎么处理（截断/摘要/检索）
- Agent 最大轮数、失败退出策略、超时、异常怎么处理
- 怎么评估 RAG / Agent（测试集、命中率、回答质量）
- 幻觉怎么防；高风险操作为什么要 HITL
- 代码质量：怎么组织项目、怎么做 review、怎么加测试

**AI 运维 / 部署运维（初级）**
- Linux 常用命令、权限、进程/端口/日志排查（`ps/top/netstat/ss/tail -f/journalctl`）
- Docker：镜像分层、volume、网络、compose 编排、健康检查、日志
- CI/CD：GitHub Actions 流程（构建→测试→部署）
- 监控：健康检查、指标、告警思路（不必吹 K8s 精通）
- 发布与回滚：怎么灰度/回滚、数据库变更怎么处理
- 安全：密钥管理（环境变量/secret）、最小权限、端口与安全组

## 八、诚实的预期管理

1. **AI 运维岗比你想的难**：真正高薪的 AI 运维要 K8s/GPU/推理服务/可观测体系，2–4 周达不到。你的可达层级是 **"AI 应用部署运维/交付运维（初级）"**——先投这一层，别去刚 SRE。
2. **Agent 开发岗更现实**，但卡在 Python 手写 → 每天 30 分钟手写**一天都不能停**。
3. **不要新开项目**：把现有项目升级成"有 CRUD + CI/CD + 监控 + 测试"的工程化项目，比第二个半成品强得多。
4. **投递 > 学习**：已毕业 3 个月，空窗期是硬伤，先上车再升级（含兜底岗）。

## 十、压缩版：2 周冲刺"能面能投"（6 周是深度线，不是等待线）

> **结论：你不需要等 6 周才开始找工作是现在就要找。**
> 6 周线是"能力补齐到你满意的水平"；真正决定有没有面试的是**这两周的动作 + 投递量**。

### 关键认知：面试门槛比你想象的低
| 面试要考你的 | 需要多久补 | 说明 |
|---|---|---|
| 手写基础 Python（循环/字典/切片） | **1–2 周** | 不是 LeetCode 难题，练 30 道就够用 |
| 讲清自己的项目（3 工具/评测/部署） | **2–3 天** | 读代码 + 复述，不是学新东西 |
| CRUD 基础（SQL + FastAPI 5 个接口） | **3–5 天** | 能跑通就能讲 |
| Docker 部署 | **已有** | 你项目已经上线了 |
| Git / 分支 / PR | **1 天** | 已经会 push/pull，补分支与 PR |

**→ 所以"能面能投"大约 2 周，而不是 6 周。**

### 2 周冲刺表（每天 2h + 每天投递 20–30 家）
| 天 | 手写 30min | 主线 60min | 读代码 20min |
|---|---|---|---|
| D1–D2 | 3 题/天（列表字典边界） | 读 `day21.py` 全文件 + 能口述三工具与数据流 | 写 3 条 review |
| D3–D4 | 3 题/天 | SQL 增删改查 4 条 + 参数化查询；`monitoring.db` 实操 | 读 `rag_eval.py` |
| D5–D6 | 3 题/天 | FastAPI 做出 `/datasets` 的 GET/POST（Pydantic 校验） | 读 `io`/`api_rag.py` |
| D7 | 复盘错题 | **简历两版定稿**（Agent 开发版 / 运维版）+ 打招呼话术 | — |
| D8–D10 | 3 题/天 | 补 PUT/DELETE + Swagger 自测截图；项目加 `/health` | 读 FastAPI 官方示例 |
| D11–D12 | 3 题/天 | 服务器 `git pull && bash deploy.sh` 部署新版（链接要新） | 写 3 条 review |
| D13–D14 | 3 题/天 | **模拟面试 2 轮**（我当面试官）+ 按反馈补漏 | — |

### 之后（第 3–6 周）：边面试边补深度
CI/CD（GitHub Actions）、监控（Uptime Kuma/Prometheus）、pytest、Agent 记忆/多轮/日志留痕、评测扩到 50 题 —— 这些是**二面/涨薪/后续跳槽**用的，**不阻塞投递**。

### 三条铁律
1. **投递从今天开始**：每天 20–30 家（Agent 开发 6 成 / 部署运维 2 成 / 兜底 2 成）
2. **手写不断**：一天不练就退步，这是你唯一的硬门槛
3. **面试后的反馈 > 闭门学习**：被问倒的题当晚补，第二天再投同类岗
