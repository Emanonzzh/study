## 一、一句话版（10 秒，放自我介绍里）

> "我做了一个**遥感地质灾害智能问答系统**：把《地质灾害防治条例》做成 RAG 知识库，再挂两个真实数据查询工具和一个形变风险打分工具，用 LangGraph 的 `create_agent` 做多工具 Agent，最后用 Docker 部署到阿里云，公网可以访问。"

## 二、1 分钟版（口述稿，照着说）

> "我这个项目叫**遥感监测智能助手**，背景是我遥感专业出身，想找一个能把**领域数据 + 大模型**结合起来的落地场景。
>
> 它解决三个问题：**查法规、查数据、判风险**。
> - 查法规：我把 gov.cn 的《地质灾害防治条例》切分、embedding 存进 Chroma，做成 RAG 问答，回答必须带依据；
> - 查数据：把国家数据中心的真实数据集元数据放进 SQLite，做了一个 SQL 查询工具；
> - 判风险：我建了一张形变时间序列表，用**规则打分**算风险等级——速率超阈值 +40、后期加速 +30、异常突变 +30，分级低/中/较高。
>
> 这三个能力封装成**三个工具**，用 LangGraph 的 `create_agent` 让大模型自己决定调哪个；输出按"数据概况/形变分析/风险等级/法规依据/结论"分节，末尾带免责声明。
>
> 工程上：FastAPI 提供 API、Streamlit 做网页、Docker 部署到阿里云 ECS，公网可访问；我还做了 **RAG 效果评测**，用 12 道题的测试集对比不同切片和检索参数，把检索命中率从 **83% 提到 100%**。"

## 三、3 分钟版（按面试官兴趣挑段讲）

**第 1 段：为什么做（30 秒）**
> "我是遥感专业转 AI 应用，最想证明的是**我能把专业领域的数据真正用起来**。遥感领域有很多非结构化资料（法规、规范）和结构化数据（监测数据集、形变时序），刚好对应 RAG 和工具调用两种典型场景，所以我把它们合成了一个 Agent。"

**第 2 段：怎么做的（60 秒）**
> "整体分四层：
> ① **数据层**——真实法规 txt、SQLite 里 3 条国家数据中心真实数据集元数据、18 期形变时间序列（示例数据，我在 source 字段标注了"示例演示数据"）；
> ② **能力层**——三个 `@tool`：法规向量检索 `query_regulation`、SQL 查询 `query_dataset`、风险打分 `risk_assessment`；
> ③ **决策层**——`create_agent(llm, [三个工具])`，工具的描述（docstring）就是给大模型的路由说明；
> ④ **交付层**——Streamlit 网页 + FastAPI 接口，Docker 打包，部署到阿里云 ECS（Ubuntu 22.04），8501 端口。"

**第 3 段：技术难点 + 怎么解决的（60 秒，**这是加分重点**）**
> "遇到三个真问题：
> **第一，工具被误调用**。我问"什么是 SBAS-InSAR"，大模型居然去调了我的风险评估工具。原因是 docstring 只写了"计算地区风险评分"，没写**什么时候不该调用**。我改成明确边界——"仅当用户询问某区域形变风险/等级时调用，概念解释、数据集查询、法规问答请用别的工具"，误调就消失了。**工具描述其实就是给 LLM 的路由器**。
> **第二，检索质量不稳定**。我一开始 chunk_size 用 100，切得太碎、语义断裂，有些问题检索不到对应条款。我做了评测：12 道题、期望关键词，跑了四组实验（切片 100/400 × k 2/4），命中率从 10/12 提升到 12/12，最优是 400 加 k=4。但我没直接把 k 拉很大——因为 k 越大 token 越贵、噪音越多，**k 应该取"最小够用"**。
> **第三，幻觉**。有次问青藏的数据集，模型回答里出现了一个元数据里根本没有的速率数字——这就是典型的"模型补充不存在的信息"。我的处理是：RAG 的 prompt 里写死"材料里没有就说知识库中没有相关信息"，并且把这次幻觉**存档当反面案例**。"

**第 4 段：结果与收获（30 秒）**
> "结果是一个公网可访问的完整应用：能答法规、查数据集、给风险分级，输出结构化报告并带免责声明。收获最大的是**评测思维**——以前我只会'跑通了'，现在我知道要用测试集证明'效果好'，以及怎么在效果和成本之间取舍。"

## 四、架构与数据流（能画出来最好，画不出就用嘴讲）

```
用户提问
   ↓
Streamlit 网页 / FastAPI 接口
   ↓
Agent（qwen-plus + LangGraph create_agent）
   ├─ query_regulation → Chroma 向量库（《地质灾害防治条例》切片+embedding）
   ├─ query_dataset   → SQLite datasets 表（真实数据集元数据）
   └─ risk_assessment → SQLite monitoring_series 表（形变时序）→ 规则打分
   ↓
结构化报告（数据概况/形变分析/风险等级/法规依据/结论）+ 免责声明
   ↓
公网访问：Docker 容器（阿里云 ECS / Ubuntu 22.04，8501 端口）
```

**口述话术**："一句话概括数据流：用户自然语言 → 模型判断该调哪个工具 → 工具从对应的数据源取结构化/非结构化数据 → 模型把结果组织成带依据的报告。"

## 五、三个工具：每个都要能讲清"做什么/输入输出/为什么这么设计"

| 工具 | 一句话 | 输入 | 返回 | 设计要点 |
|---|---|---|---|---|
| `query_regulation` | 法规 RAG 检索 | keyword（问题关键词） | Top-K 条款原文 | 切片 400、k=4（评测得出）；回答必须基于检索内容，查不到就说没有 |
| `query_dataset` | 查数据集元数据 | keyword | 数据集名/区域/方法/时间/精度/来源 | 用 SQL `LIKE` 模糊匹配三个字段；**坑：LIKE 是连续子串**，所以"青藏"能中、"青藏工程走廊"中间断开就中不了 |
| `risk_assessment` | 形变风险规则打分 | region（区域名） | 分数+等级+三项指标明细 | **不用 LLM 判断**，用确定性规则：近 3 期平均月增量>10 → +40；后半段速率>前半段 → +30；最近一期增量>历史均值 3 倍 → +30；≤30 低 / ≤60 中 / >60 较高；数据不足 4 期返回"数据不足" |

**可能追问 → 回答要点**
- *"为什么风险不用 LLM 算？"* → "风险评估要可复现、可解释，规则算出来的分数每次一样，面试官/客户能验证；LLM 只负责把结果翻译成人话。"
- *"如果区域名传错怎么办？"* → "查询返回空，工具返回'数据不足'，模型就会如实告知用户，而不是编一个分数。"
- *"SQL 注入怎么办？"* → "我用的是参数化查询（`?` 占位），不是字符串拼接。"（这点值得强调，是加分项）

## 六、四个"为什么"（面试官爱问的决策题）

1. **为什么先手写 RAG，再用 LangChain？**
   → "先手写是为了搞懂 embedding、相似度检索、切片到底在干什么；再用框架是为了工程效率。面试时我能说清框架帮我做了什么，而不是只会调 API。"
2. **为什么用 RAG 而不是把条例全文塞进 prompt？**
   → "条例很长，全文塞进去 token 成本高、还容易被无关条款干扰；RAG 只取最相关的几块，**省 token 也更准**。"
3. **为什么要做评测？**
   → "不然'效果好不好'全靠感觉。我用 12 道题的测试集 + 期望命中关键词，四组参数对比，把命中率从 83% 提到 100%，并且发现 k 存在'效果 vs 成本'的权衡。"
4. **为什么要免责声明？**
   → "这是灾害/安全相关的场景，模型输出不能当成官方预警。工程上这是**负责任 AI** 的基本动作，也是真实企业 Agent 的常见要求。"

## 七、踩坑故事（STAR，挑 2-3 个讲，数字和细节都要真）

**故事 1：embedding 批量报错**
- 现象：embedding 时报错，说批量大小非法
- 原因：阿里云 text-embedding-v3 **每批最多 10 条**，我一次传太多
- 解决：`chunk_size=10` 分批提交（注意：这是"每批条数"，跟切片长度 chunk_size 是两回事，别混）
- 收获：读文档要看限制条件，报错先看 API 约束

**故事 2：SQL LIKE 不是模糊匹配**
- 现象：查"青藏工程走廊"的数据集查不到
- 原因：`LIKE '%关键词%'` 是**连续子串**匹配，中间断开就匹配不上
- 解决：约定用短关键词（如"青藏"），并把这条写进注释/文档
- 收获：先搞清底层语义，再谈优化

**故事 3：docstring 决定工具会不会被误调**
- 现象：问概念题（"什么是 SBAS-InSAR"）触发了风险评估工具
- 原因：工具描述没写清"边界"
- 解决：改写 docstring，写明何时调用 + 何时不要调用（交给哪个工具）
- 收获：**Agent 里 prompt 不只 system prompt，工具描述也是路由策略**

**故事 4：API Key 泄漏（真实教训，讲出来是加分不是减分）**
- 现象：早期把真实 key 硬编码进代码并 push 到 GitHub
- 处理：立刻吊销 key、改成环境变量 `os.getenv("DASHSCOPE_API_KEY")`
- 收获：密钥永不入库；这也是为什么现在代码里只读环境变量

## 八、RAG 评测（V2-C，你的"深度"证据，务必讲）

**做法**：12 道法规问答题（问题 + 期望命中的关键词），脚本自动：建库 → 检索 → 判断期望关键词是否出现在 Top-K 内容里 → 计数命中。

**四组实验（chunk_size × k）**：

| 切片大小 | k | 命中 |
|---|---|---|
| 100 | 2 | 10/12（83%） |
| 100 | 4 | 11/12 |
| 400 | 2 | 10/12 |
| 400 | 4 | **12/12（100%）** |

**口述结论**："切片太小会把一句话切碎、语义断裂，检索就找不准；把切片放大到 400 并提高 k 到 4 之后命中率到 100%。但我不建议无脑加大 k——k 越大，喂给模型的无关内容越多，token 成本上升、还可能干扰回答。**评测的价值就是用数据找到'最小够用'的参数**。"

**可能追问**
- *"12 道题样本太少了吧？"* → "是，这是我这版评测的局限，所以我把结论定位成'参数相对优劣'而不是绝对精度；如果继续做，我会扩到 50+ 题并加入回答质量的评分维度。"（**承认局限=成熟**）
- *"命中就等于回答对吗？"* → "不等于，命中只衡量检索环节；回答质量还需要另一套评估（比如人工评分或 LLM 裁判），这是我下一步想补的。"

## 九、工程化与部署（面试官常问"你会不会上线"）

- **Docker**：写 Dockerfile 打包，服务器上 `docker build` + `docker run`；镜像里不写死密钥，`-e DASHSCOPE_API_KEY=...` 传入
- **阿里云 ECS**：Ubuntu 22.04，安全组开 22 和 8501；SSH 登录 → git clone → 构建 → 运行
- **两套入口**：`api_rag.py`（FastAPI，`/ask?question=...` 返回答案+来源）、`day21.py`（Streamlit 网页）
- **Git 协作**：两台电脑通过 GitHub 同步，遇到过 `push` 被拒 → `pull` 合并 → 再推的完整流程
- **一键部署**：写了 `deploy.sh`（拉代码 → 构建 → 从旧容器恢复环境变量 → 重启 → 健康检查）

**追问**：*"线上出问题怎么排查？"* → "先看容器状态和日志（`docker logs`），再看端口/健康检查；我这项目量级小，没上监控，如果要生产化我会加日志与告警。"（诚实 + 知道下一步）
